The list has two genuinely different empty situations, and the board's own total -- never the presence of a filter -- is what tells them apart: a board with no task at all offers to create the first one, whatever the query string carries, and that create control is the page's only one because list.html suppresses its toolbar button in the same situation; a board with tasks but none matching offers to clear the filters that excluded them. Both controls are secondary, as the toolbar's own Create task is: the list's primary action is "Apply filters". Dates, status labels and deadline states are never computed here: they come from the four filters in app/templating.py, and the deadline cell's whole text comes from its :func:`format_deadline` global, so the badge, the deadline column and the deadline filter cannot disagree. That global drops the relative word on a completed task -- no "Overdue", no "Due today", no "Due in N days" -- because finished work is not late, and deadline_state is the one place that rule lives, so no guard on it is repeated here. A row without a deadline states "No deadline" through the same .deadline span the dated rows use, so the column keeps one type scale and no cell falls back to body text.
