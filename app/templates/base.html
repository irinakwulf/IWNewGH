{# The page shell: the document skeleton, the header and navigation, the flash region, the 1080px content column and the footer. Every view template -- dashboard.html, project.html, the three task templates and the three error pages -- extends this file and fills exactly two blocks: `title`, the page's own words in the browser tab, which falls back to the product name; and `content`, the screen itself. Neither may be renamed or removed. The page's single top-level heading belongs to the view's content block rather than to this file -- the header's product name is plain text, not a heading -- so no screen ends up with two. The navigation's current link is computed here, server-side, from `request.endpoint`, because this application ships no JavaScript: nothing in the template tree carries a script element or an inline event handler attribute. Exactly one link can ever be marked -- Dashboard for `dashboard.index`, Tasks for any `tasks.*` endpoint (the list, the form, the detail view and the page a rejected post re-renders), and Project for `project.view`. A request that matches no route at all leaves `request.endpoint` None -- which is how a task id nowhere near a task route, and the generic error paths, render -- and then no link is marked, because the visitor is on none of the three screens. The mark follows the endpoint and never the response status, so a 404 raised from inside a task route keeps Tasks marked: the visitor is still in that section, and clearing the mark on the way to an error page would have to special-case every abort the views make. The flash region is included bare, immediately below the header, with no wrapper of its own: partials/_flash.html renders nothing when nothing has been flashed and otherwise owns the `.container` that lines a message up with the column below, so wrapping it here would double that container. Every value this file renders is a literal declared in it or a URL built by `url_for`; no request parameter is read and no user text reaches it, so there is nothing here to escape and no filter or conversion that could bypass the autoescaping Jinja applies to every `.html` template. The classes are the ones app/static/css/app.css defines -- `.header`, `.nav`, `.container`, `.footer` and the `.row` primitive -- and every style comes from that stylesheet: this file carries no inline style attribute, no second stylesheet, no font, no icon and no image. #} {%- set product_name = 'Taskboard' -%} {%- set endpoint = request.endpoint or '' -%} {% block title %}{{ product_name }}{% endblock %}
